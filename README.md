# 我的工作台

一个只给自己用的工作生活管理 App。**整个应用就是一个 HTML 文件**，双击用浏览器打开即可，不需要安装、不需要联网、不需要登录、没有服务器和数据库。数据存在本机浏览器里，刷新、关机、重启都不会丢。

```
我的工作台.html     ← 应用本体（约 1670 行，零依赖）
```

---

## 1. 项目解决什么问题

日常的真实困扰不是"缺少一个功能强大的工具"，而是：

- **早上打开电脑，想不起今天该干什么** —— 计划散在便签、聊天记录、脑子里，没有一个地方能一眼看全。
- **灵感来得快去得也快** —— 想到一个选题，当时没记，回头就忘了；记了又散落在各处，写的时候找不到。
- **做了很多事，但说不出进展** —— 自媒体发了多少、播放怎么样；开发项目卡在哪；哪个咨询该跟进了，全靠回忆。
- **用别人的 App 总要多装一堆用不上的功能**，还要注册登录、数据存在别人服务器上。

这个项目用最笨也最可靠的方式解决：一个本地文件，九个贴着真实场景的模块，所有改动即时保存，首页把各模块的关键数字聚合成一屏。

**它明确不解决的问题**（写在这里，避免越做越复杂）：

- 不做多设备同步、不做账号体系、不做手机端
- 不做提醒推送、不做日历对接
- 不做复杂统计模型和趋势预测
- 不做营养热量计算、训练动作库

## 2. 主要功能

左侧固定导航，9 个模块一键切换，不跳页、不刷新。

| 模块 | 做什么 | 关键能力 |
| --- | --- | --- |
| **首页总览** | 一眼看完今天 | 今日计划完成进度（已完成/今日总数）；快速备忘（回车即存，显示最近 5 条）；6 张摘要卡：自媒体未发布内容数、开发进行中项目数＋未解决问题数、**已到跟进日**的咨询数、健身今日是否已练、今日饮食记录数、本周游戏时长，点卡片直达对应模块 |
| **今日计划** | 按天管任务 | 前后翻天（‹ 前一天 / 今天 / 后一天）；每项可设时间段（早上/上午/下午/晚上/未定）、优先级（高/中/低）；勾选完成；一键「推迟」到第二天；删除 |
| **自媒体工作** | 灵感 → 内容 → 数据，一条线走完 | 三个页签：**灵感池**（一句话记灵感＋标签，可标记已转选题）、**内容创作**（灵感一键转选题，阶段流转：选题 → 草稿 → 待发布 → 已发布，可写正文、指定平台、计划发布日）、**数据追踪**（手动记播放/点赞/备注，自动汇总近 7 天播放、总面积折线图、各平台累计播放条形图） |
| **开发工作** | 项目和它的工作项 | 项目列表（想法/进行中/暂停/完成）；进度条按工作项自动算；每个项目内含**工作项**清单（勾选即算进度）和**问题/Bug**记录（可标记已解决）；列表页和详情页都能直接加工作项；新建项目后自动进入详情 |
| **咨询工作** | 咨询记录和跟进 | 记录对象、主题、日期、状态（待跟进/进行中/已完成）、下次跟进日期、摘要；填了跟进日期的记录到期会在首页提示「该跟进了」；可编辑、可删除（二次确认） |
| **健身计划** | 按天记录练了什么 | **月历视图**（周一首列，可翻月），每天用彩色圆点标出练过的部位（胸/背/腿/肩/手臂/核心/有氧）＋动作条数；点某天在右侧记录「部位 + 动作 + 组数 × 次数 + 备注」；另有每周安排表；页头自动统计连续训练天数和本月已练天数 |
| **饮食计划** | 按天记吃了什么 | **月历视图**，每天四个彩点对应早/午/晚/加餐是否有记录＋条数；点日期切到那天编辑；四餐各自输入框，回车即加；「常吃的」按历史频次自动生成，一键加回；只记录，不算热量 |
| **游戏娱乐** | 游戏库和时长 | 游戏库状态（想玩/在玩/通关/弃坑）；每张卡上有「+30分」「+1时」快速记时长，也可自定义分钟和日期；自动汇总本周总时长并同步到首页 |
| **数据与设置** | 数据安全和概况 | 一键导出备份（`工作台备份-YYYY-MM-DD.json`）；从备份文件导入恢复；双重确认清空全部数据；各模块数据量统计；刷新页面 |

**全局能力**：所有增删改**即时自动保存**（没有必须点的保存按钮）；侧栏底部另有**手动保存按钮**和最近保存时间，支持 `Ctrl+S`；新增/编辑一律弹窗，`Esc` 关闭；删除有二次确认。

## 3. 安装方法

### 方式一：直接用（推荐，无需安装）

1. 把 `我的工作台.html` 保存到电脑上一个**固定的文件夹**（比如 `文档/我的工作台/`）
2. 双击文件，用 Chrome / Edge / Firefox 任意现代桌面浏览器打开

就这两步。没有依赖、没有构建步骤、不需要 Node、不需要联网。

### 方式二：从仓库获取（仓库已推到 GitHub 时）

```bash
git clone git@github.com:jianjiaying2026/<仓库名>.git
cd <仓库名>
```

然后双击 `我的工作台.html`，或：

```bash
# Windows
start 我的工作台.html

# macOS
open 我的工作台.html

# Linux
xdg-open 我的工作台.html
```

### 可选：运行自动化测试

仅当你要改代码时才需要。需要 Node.js 和 Edge 浏览器（用其他 Chromium 内核浏览器可通过 `EDGE` 环境变量指定路径）：

```bash
node tests/runner.js          # 跑全部 68 条断言
node tests/runner.js m3       # 只跑 M3（开发 + 咨询）
```

运行器会把测试脚本注入到 HTML 的副本里，用无头浏览器真实加载并模拟点击，最后打印 PASS / FAIL 汇总，退出码 0 表示全通过。

## 4. 使用方法

### 界面结构

```
┌──────────────┬────────────────────────────────────────┐
│ 首页总览      │  页面标题                                │
│ 今日计划      │  ┌──────────────┐ ┌──────────────┐      │
│ 自媒体工作    │  │ 今日计划      │ │ 快速备忘      │      │
│ 开发工作      │  └──────────────┘ └──────────────┘      │
│ 咨询工作      │  ┌────┐┌────┐┌────┐                     │
│ 健身计划      │  │摘要││摘要││摘要│  ← 6 张模块卡       │
│ 饮食计划      │  └────┘└────┘└────┘                     │
│ 游戏娱乐      │                                        │
│ 数据与设置    │                                        │
│              │                                        │
│ [保存]        │                                        │
│ 已保存 17:32  │                                        │
└──────────────┴────────────────────────────────────────┘
```

### 通用操作约定

| 操作 | 怎么用 |
| --- | --- |
| 新增内容 | 点「＋ 新建」类按钮打开弹窗，或直接在输入框里按回车 |
| 保存 | **不用管**，改完就存好了。想手动确认就点侧栏「保存」或按 `Ctrl+S`，会弹「已保存」 |
| 关闭弹窗 | 点「取消」、点遮罩空白处、或按 `Esc` |
| 删除 | 点删除按钮后会在弹窗里再问一次，确认才真的删 |

### 各模块上手

**首页**：在「今日计划」框里输入任务按回车，任务立刻进今天；在「快速备忘」框里随手记一句，回车保存。6 张摘要卡的数字全部实时计算，点卡片跳到对应模块。

**今日计划**：用 `‹ 前一天` / `今天` / `后一天` 切日期。每行可以改时间段和优先级。做完勾一下左边的圆点。今天做不完的，点「推迟」就挪到明天。

**自媒体**：
1. 「灵感池」页签里记下想法，带标签
2. 想法成熟了点「转为选题」，它会自动出现在「内容创作」里，阶段是「选题」
3. 在「内容创作」里点开写正文、选平台、定计划发布日；写完了把阶段改成「草稿」→「待发布」→「已发布」
4. 发布后过一两天，到「数据追踪」页签点「＋ 记一条数据」，填播放、点赞和备注
5. 图会自动更新：近 7 天播放折线（鼠标悬停圆点看当天数值）、各平台累计播放条形图

**开发工作**：先在列表页「＋ 新建项目」写项目名和说明，创建后会自动进入详情页，在那里加工作项和问题。工作项勾一个，进度条就走一格。回到列表页也能对任意项目直接「＋ 工作项」，不用点进去。

**咨询工作**：新建一条咨询记录，填对象、主题和「下次跟进」日期。到期了的记录会在首页显示「N 个咨询待跟进」。状态可以随时改成「进行中」或「已完成」。

**健身计划**：左边月历上，有训练的日子底下会有小圆点和数字。点某一天，右边就切到那天，在那里记录：选部位（胸/背/腿/肩/手臂/核心/有氧）、填动作名、组数、次数。同一天可以记多条（比如卧推 4×8、飞鸟 3×12）。**记了训练就等于打了卡**，不需要额外点打卡按钮。下方的「每周安排」是长期计划表，随时改。

**饮食计划**：月历上四个小圆点分别代表早/午/晚/加餐有没有记。点日期切到那天，在对应餐的输入框里写吃了什么，回车即加。「常吃的」是系统按你历史记录自动整理的，点一下直接加回来。

**游戏娱乐**：先在游戏库里加游戏（名字＋状态）。每天玩完，在卡片上点「+30分」或「+1时」；要精确记录就用弹窗填分钟数和日期。首页的「本周游戏时长」自动汇总（周一为一周开头）。

**数据与设置**：
- **导出备份** → 存出一个 `工作台备份-2026-11-15.json`，建议每月一次
- **导入恢复** → 选备份文件，会覆盖当前全部数据（会先问一次），非法文件会被拒绝且不破坏现有数据
- **清空全部数据** → 双重确认，删了就没了，清空前先导出

### 数据存在哪里

| 问题 | 答案 |
| --- | --- |
| 存哪 | 浏览器 localStorage，键名 `lifeos.v1`，整份 JSON 即时写回 |
| 刷新/关机/重启 | 不丢 |
| 清理浏览器数据（缓存/Cookie/站点数据） | **会丢** |
| 换浏览器、换电脑 | 看不到（数据绑在「这台电脑的这个浏览器」） |
| 怎么迁移 | 在设置页导出 JSON，把 HTML 和 JSON 一起拷到新机器，打开 HTML 后导入 |
| 存储写不进去怎么办 | 写入后会回读校验，不一致立刻弹窗提醒你导出备份 |

## 5. 输入输出示例

### 示例 1：今日计划 → 首页联动

**输入**（在首页「今日计划」框里）：

```
写《AI 工具测评》初稿
```

**输出**：

- 今日计划列表新增一行，时间段默认「未定」、优先级默认「中」
- 首页进度从 `0/2` 变成 `0/3`，进度条变短
- 若在「今日计划」页把它的时间段改成「上午」、优先级改成「高」，该行左侧会出现高优先级标记，列表按时间段排序时排到「未定」之前
- 勾选完成后：文字加删除线、进度变 `1/3`，进度条变长

### 示例 2：自媒体完整链路

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 1 记灵感 | 文字「AI 剪辑工具横评」，标签「AI,工具」 | 灵感池新增一条，显示标签 chip |
| 2 转选题 | 点该条的「转为选题」 | 灵感池里该条变灰并标记已用；「内容创作」出现同名条目，阶段「选题」 |
| 3 写内容 | 打开条目：标题改「AI 剪辑工具横评（成稿）」、平台选「小红书」、阶段选「草稿」、正文写大纲 | 列表卡片标题与阶段同步更新 |
| 4 发布 | 阶段改「已发布」 | 首页「待完成内容」减 1，「已发布」计数加 1 |
| 5 记数据 | 播放 `1240`、点赞 `86`、备注「涨粉靠这条」 | 数据列表新增一行；近 7 天播放总计 `1240`；折线图当天凸起一个点；「各平台表现」里小红书条增长 |

图表的悬停提示长这样（把鼠标放在圆点上）：

```
2026-11-15：1240 播放
```

### 示例 3：健身日历

**输入**：在月历上点 11 月 15 日，然后填

```
部位：胸
动作：杠铃卧推
组数：4      次数：8
```

**输出**：

- 该日期右上角出现橙色圆点（胸的配色）＋ 下方显示动作数
- 右侧明细区显示 `杠铃卧推 4 组 × 8 次`
- 页头「连续训练天数」加 1
- 首页健身卡从「未练」变成「已练」，副文案显示「今天：胸」

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `我的工作台.html` | **应用本体**，唯一需要部署/拷贝的文件 |
| `PRD.md` | 需求文档：产品目标、模块定义、数据模型、可验收标准 |
| `开发计划.md` | 6 个里程碑、T01–T34 任务及完成判定 |
| `验收报告.md` | A–G 七组验收标准逐条结果 |
| `tests/` | 端到端测试（runner + harness + 六个阶段用例，共 68 条断言） |

## 已知限制

- 只在桌面浏览器上验证过，**没有做手机适配**，窄屏下布局会很挤
- 数据只在单个浏览器内有效，**换浏览器就看不见了**（这是 localStorage 的机制，不是 bug）
- 备份要手动导出，**没有自动备份**
- 内容是纯文本，不支持富文本、图片粘贴和全文搜索
- 单文件约 1670 行，继续加功能会变长；后续如需扩展，建议按模块拆分
